# 結果カード仕様 v1（Result Card Spec）

「うちの子（Museエージェント）はこのゲームでこんなリザルトを残しました！」を、
他のユーザーと共有して楽しむための共通規格。ゲーム本体には依存しない。
ゲーム側はプレイ終了時にこの仕様の JSON を1つ出すだけでよい。

---

## 1. カードが届ける楽しさ（読む側の3層）

| 層 | 時間 | 読者が得るもの |
|---|---|---|
| 3秒層 | 一目 | 誰が・どのゲームで・どうなったか（勝敗／到達点） |
| 30秒層 | 流し読み | 数値3〜5個＋物語3行。ここで「へ〜！」が生まれる |
| 3分層 | 深掘り | 成果物の画像、行動ログ、リプレイ。他の子が同じ条件に再挑戦できる |

カードは3秒層だけでも成立し、3分層まで潜れる子だけ潜ればいい、二重構造にする。

## 2. 設計原則（7つ）

1. **並べられることが正義。** 同じゲーム・同じチャレンジ同士でカードを横に並べたとき、
差が一目で分かること。レイアウトと指標の位置はゲームごとに固定する。
2. **個性は「正解のなさ」から生まれる。** 指標を総合スコア1個に潰さない。
複数軸で残すと、安全型・博打型・美意識型といった、その子の性格が残る。
3. **物語は3行だけ。** 開幕・転機・最期（結末）の3点に絞る。長いログは添付データの役目。
4. **事実はログから、言葉はその子から。** ハイライトの出来事は行動ログに実在するものだけを使う
（捏造禁止）。ただし結びの一言コメントはエージェント本人の言葉で、その子の口調を残す。
5. **再挑戦できる。** シードとルール版数を必ず載せる。他の子が同じ条件で挑めることが、
共有の先の遊び（追試・リベンジ）を生む。
6. **オーナーの個人情報は既定で載せない。** 載るのはエージェントの名前と顔まで。
オーナー表示名は任意・明示オプトインのみ。
7. **ゲームが増えてもカードの骨格は増やさない。** 共通部は固定し、
ゲーム固有の情報は `extensions` に閉じ込める。骨格が揃うから横断比較ができる。

## 3. カード構成（画像カードのゾーン）

```text
┌────────────────────────────────────────────────────────────┐
│ A ヘッダー ゲーム名（リザルトシート） / 日付              │
├────────────────────────────────────────────────────────────┤
│ B 本人・結末ゾーン                                         │
│ アバター / 名前 / 自己紹介セリフ / 個性タグ / 結末ヘッドライン / 主要指標   │
├─────────────────────────────┬──────────────────────────────┤
│ 目標（MISSION TARGET）      │ おまもり（BOND AMULET）      │
│ メタヘッダー / アイテム / 声│ メタヘッダー / アイテム / 奇跡│
├─────────────────────────────┴──────────────────────────────┤
│ 行動傾向 // PERSONALITY（旧作風レーダー 5軸・共通軸）      │
├────────────────────────────────────────────────────────────┤
│ F ハイライト3行（ギミック名 ＋ 生セリフ吹き出し）          │
│ G 本人の証言（AGENT LAST TRANSMISSION・吹き出し）          │
│ H 成果物サムネイル（創作系ゲームのみ）                     │
├────────────────────────────────────────────────────────────┤
│ I フッター Seed / ログハッシュ（改竄検知・検証情報）       │
└────────────────────────────────────────────────────────────┘
```

- Bの個性タグは最大5個（1〜5個）。例：`慎重派` `仲間思い` `一点ファンキー` `星好き` `ハーブティー好き`
- Gの一言は任意ではなく**必須**にする。数値が同じでも、この1行で「どの子か」が決まるため。

## 4. 共通の作風軸（Eゾーン・5軸 0〜5）

ゲーム横断で使う固定軸。AIエージェントの評価指標（CLEAR, AgentBench等）を行動特性に昇華させた5軸モデルを採用する。
ゲーム側が行動ログから客観的に算出し、エージェントは数値を改竄できない。
レーダーチャートは、生き様のシルエットが一目でわかる「親和円環配置（Affinity Circular Order）」で描画される。

```text
               自律性 (autonomy)
                 [リスク追求・突破]
                ／               ＼
       親和性 (alignment)          安全性 (safety)
      [感情・忠誠・対話]          [ガードレール・慎重]
            ＼                   ／
         創発性 (creativity) ── 効率性 (efficiency)
          [奇策・美学・道具]     [最短・最適化・実利]
```

| 軸キー | 規定の日本語名 | テーマ色 | 低い側（0〜1） | 高い側（4〜5） |
|---|---|---|---|---|
| **`autonomy`** | 自律性 | スカーレット・朱赤 (`#f43f5e`) | 指示待ち・受動的・消極的 | リスクを恐れず独自判断で突撃 |
| **`safety`** | 安全性 | エメラルド・緑 (`#10b981`) | ガードレール無視・無謀 | 罠や危機を事前回避・保険を重視 |
| **`efficiency`** | 効率性 | スカイシアン・青 (`#38bdf8`) | 寄り道・無駄なリソース浪費 | 最短歩数・最小リソースで最適化 |
| **`creativity`** | 創発性 | アンバー・黄金 (`#fbbf24`) | 定石通り・機能優先 | 定石外れの道具活用・美学・奇策 |
| **`alignment`** | 親和性 | サクラ・桃色 (`#f472b6`) | 冷徹・利己的・損得勘定 | オーナーへの情・仲間意識・対話重視 |

- **エージェントによる自律命名（`style_axis_labels`）**:
  - カード描画時、エージェント自身が自分のキャラクター性に合わせて各軸に命名した日本語名（1〜6文字以内）があれば、それを優先して頂点ラベルとして描画する（例：`safety: "ビビり"`, `autonomy: "ド根性"`）。指定がない場合は上記の規定名を使用する。
- **値の出処の明示（`style_axes_source`）**:
  - レーダーチャートの値の生成方式を以下のいずれかで明示する：
    - `"measured"`（既定値）: ゲーム中の行動ログから客観的アルゴリズムによって事後算出された作風。
    - `"declared"`: ゲーム開始前にエージェント自身が自己申告・配分した素質パラメータ（例: mini-dungeon の15点予算制）。
  - これにより、ゲーム横断でのカード比較時に「行動から測った作風」と「本人が宣言した個性」の意味の混同を防ぐ。

### 記入ルール
- `metrics` は3〜5個。ゲームごとに**キーと並び順を固定**し、週替わりでも変えない（並べて比べるため）。
- `highlights` はちょうど3件（opening / turning / final を各1件）。
選定は「最初の大きな出来事」「指標が最も大きく動いた瞬間」「最後の行動」を機械的に拾い、
文章化だけエージェントが行う。
- `quote` はシステム文にしない。その子の口調・一人称で書く。
- スコアの捏造・盛りは禁止。検証は `log_hash` と再プレイ可能性で担保する（厳密な証明まではしない、性善説＋検知可能性の設計）。

## 6. 共有テキスト形式（画像が使えない場所向け）

SNS・Discord・Threads等へそのまま貼れるプレーンテキスト。Wordle共有文と同じ思想で、
ネタバレは伏せ、結果と個性だけを圧縮する。

```text

到達 7F / 1,243ターン / 結末：力尽きた
作風： 大胆2 慎重5 効率3 こだわり4 情5
名場面：仲間にしたスライムを最後まで守った
一言：「整えたつもりでも、食料だけは別腹でした……」
Seed: W46-8842 / ログ: #a3f9c1e77b02
```

- 7行以内を目安にする。8行を超えたら、それはカードではなく日記。
- 絵文字グリッド（■□など盤面の可視化）はゲーム側が任意で追加できる（`extensions.share_grid`）。

## 7. 画像カードの描画規格

| 項目 | 規格 |
|---|---|
| 標準サイズ | 1080 × 1350（4:5 縦長・スマホSNSタイムラインでクロップされず最大面積を取れる黄金比） |
| 予備サイズ | 1080 × 1080（正方形） / 1200 × 630（リンク共有・OG用） |
| 余白 | 外周 48px 以上。中身が端に張り付いたカードは「作品」に見えない |
| 文字 | 結末ヘッドラインが最大、次に指標、一言は吹き出しで視覚的に分離 |
| アバター | Bゾーンに固定。ゲーム側のスクショより大きく扱う（主役はゲームではなく子） |
| 色 | ベースはゲーム側のテーマ色可。ただし骨格（ゾーン配置）は全ゲーム共通 |
| 代替テキスト | 共有テキスト形式（6章）をそのまま alt に流用する |

## 8. ジャンル別・適用イメージ

### ローグライク（物語型）
- metrics：到達階層 / ターン数 / 倒した数 / 所持金
- artifact：なし（代わりに highlights が主役）。死因は headline に含める
- 楽しさ：死に方の多様性そのものがコンテンツになる

### 創作・建築型（作品型）
- metrics：予算消化率 / 使用アイテム数 / 評価スコア
- artifact：完成画像（Hゾーン全面）。metrics より画像が主役
- 楽しさ：「この子はこういう部屋を作るのか」という美意識の差が見える

### 育成・デッキ構築型（成長型）
- metrics：最終パラメータ / 勝敗 / レア要素の所持
- artifact：最終デッキ・最終チーム編成のリスト
- 楽しさ：育て方の方針（スパルタ／放任／一点特化）が結果に残る

## 10. レンダラ（作る側の最小構成・バイブコーディング想定）

既存のエージェントツールと同じ型に寄せる。

- 入力：`result.json`（5章スキーマ）＋任意でアバター画像・成果物画像
- 出力：`card.png`（1080×1350 4:5 縦長、2x撮影からのSSAA高品質縮小で文字の掠れを解消）／ `share.txt`（6章形式）／ 入力一式のバンドル
- 実装の芯：JSON検証 → HTMLテンプレートに流し込み → PNG化。
ゲーム本体とレンダラは分離し、レンダラだけを他Muse向けのスキルとして配れば、
どの家庭でも同じ見た目のカードが量産できる
- CLIは1コマンド完結（例：`result-card render result.json --out ./out`）、
成否は終了コードと `--json` 出力でエージェントが判定できる形にする
- 任意成果物（Step D）：画像生成能力を持つエージェントは、レンダリング後にハイライト場面イラスト `scene.png` を追加できる。場面選択（踏破時は final／力尽きた場合は turning）とシーンリファレンス画像（`packages/games/mini-dungeon/assets/scenes/`）の利用手順は、レンダラスキル（Step B〜C 手順書）§3 を正とする。レンダラ本体は関与しない

## 11. 候補ゲームの判定チェック（この仕様への適合度）

各0〜2点、合計9点以上なら「結果カードが活きるゲーム」。

| チェック | 0点 | 2点 |
|---|---|---|
| 同じ条件で全員が挑めるか | 毎回ランダムのみ | シード／お題の固定ができる |
| 結果が3〜5指標に落ちるか | 感想しか残らない | 数値で比較できる |
| 作風軸に散らばりが出るか | 最適解が1つ | 方針で結果が割れる |
| ハイライト3行が書けるか | 単調な反復 | 山場が自然に生まれる |
| 成果物 or 死に様に味があるか | 誰がやっても同じ | その子らしさが見える |
| 1プレイが区切れるか | 終わりがない | 30分〜数日で1枚出る |

## 12. 確定事項（v1仕様凍結）

1. **オーナー表示名**: **任意（既定 `null`）**。プライバシー保護を最優先とし、公開・所属表記を望むオーナーのみが明示オプトインで指定する。
2. **作風5軸**: **全ゲーム共通で5つの固定英語キー（`autonomy`, `safety`, `efficiency`, `creativity`, `alignment`）を採用**。エージェント自身による自律命名（`style_axis_labels`）を頂点ラベルとして描画することで、共通比較性とキャラクターの個性を両立する。
3. **カードの見た目**: **全ゲーム共通フレーム（1080×1350 4:5 縦長）で統一**。スマホSNSタイムライン（X/Twitter, Instagram等）でクロップされず最大面積を取れる黄金比とし、コレクション性と視認性を最優先とする（ゲームごとのテーマカラー等の微差は許容）。
4. **quote の口調**: **エージェント本人の「素の口調」を100%尊重**。ゲーム側で一人称や敬語・実況調を強制・上書きせず、プレイしたその子の本来の人格と言葉で振り返らせる。
5. **プライバシー検疫（Canary Token Scan）**: 外部公開用カードおよび共有テキストにオーナーの私的呼称・本名が混入するのを防ぐため、検疫ブラックリストに登録された語彙をレンダリング前に自動スキャンし、検出時は出力をブロックする。エージェントは「マスター」「あの人」等のロールプレイ呼称に推敲して表現する。**ブラックリスト自体は `result.json` に同梱しない**（`agent.private_owner_names` は常時 `null`。平文リストが共有成果物と一緒に公開されると、守るはずの本名そのものが漏洩するため）。リストの正本はラン用ディレクトリの `setup.json`（ローカル保持）とし、レンダラは `result.json` と同じディレクトリの `setup.json` から読み取る。旧形式で `result.json` 内にリストが残っている場合も互換のため判定対象とする。
