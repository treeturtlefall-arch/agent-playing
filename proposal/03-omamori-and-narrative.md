## 1. プレイヤー介入の核：「おまもり」とAIのでっち上げシステム

人間（オーナー）の「送り出し時の微小介入」と、AIの「妄想力・ユーモア」を融合させた本企画の最重要ギミック。

### 1.1 授与と制約
- **自由入力**: 出発前、人間は自由な自然言語でエージェントに1つだけおまもりを持たせることができる。
- **形式・文字数上限**: **名詞句1つ、30字以内**（例:「冷えたカレーパン」「お母さんの手編みマフラー」「謎の赤いボタン」）。
- **効果の独立原則（ルードナラティブ分離）**:
  - **エンジンはおまもりの文字列を一切解釈しない。**
  - 「何でも防ぐ究極の盾」と書いても、エンジンにとっては単なるラベルであり、チートやプロンプトインジェクションは無効化される。

### 1.2 発動シーケンスと効果
- **使用回数**: ダンジョン攻略中、**エージェント自身の判断で1回限り**使用可能。
- **発動タイミング**: **判定結果（大成功〜大失敗）を確認した直後、HP減少が確定する前**。
  - 「うわっ、大失敗した！ここで死ぬわけにはいかない！」とエージェントが判断して使う。
- **固定効果**: 判定ランクを**機械的に「+1段階上昇」**させる。
  - `大失敗 → 失敗`
  - `失敗 → 成功`
  - `成功 → 大成功`
  - ※すでに `大成功` の場合はそれ以上上昇しないため使用不可（CLIで指定された場合は終了コード `1` で拒否し、おまもりは消費されない）。
- **推奨発動ガイダンス（`suggest_omamori`）**:
  - エンジン側では任意タイミングでの使用を許可しつつ、CLI出力において**「大失敗（出目2またはDiff $\le -3$）」または「確定後の残りHPが2以下（瀕死域）」**の絶体絶命時にのみ `suggest: true` が通知される。
  - 序盤の微小な軽傷（HP10→9等）での無駄遣いや、終盤での抱え落ち（未使用死）を防ぎ、劇的な山場での発動を促す。
- **瀕死救済の非対称性（ドラマの創出）**:
  - HP1の瀕死時、`失敗 (-1)` をおまもりで `成功 (±0)` に引き上げれば奇跡的に生き残る。
  - 一方、`大失敗 (-2)` をおまもりで `失敗 (-1)` に引き上げても、HPは0になり力尽きる。
  - ➔「おまもりを握りしめて必死に抗ったが、一歩及ばず倒れた」という最高の死に様ドラマが生まれる。

### 1.3 AIによる完全でっち上げ（こじつけ）
- おまもり使用時、AIエージェントは**「なぜそのアイテムによって危機を脱出（あるいは軽減）できたのか」の理由を全力でこじつけて描写**する。
- 突拍子もないアイテムとダンジョンの危機が、エージェントの屁理屈と世界観で結びつく面白さを楽しむ。

## 2. リザルトの2層構造（冒険ログ vs 結果カード）

読者の視聴時間・深度に合わせた明確な2層構造を採用する（カード仕様の詳細は [`specs/result-card-spec-v1.md`](../specs/result-card-spec-v1.md) 参照）。

```text
┌─────────────────────────────────────────────────────────────┐
│ 冒険ログ（3分層）：adventure.md & logs/<seed>_<agent>.jsonl │
│ ・全階層のイベント、選択、ダイス目、判定、HP推移            │
│ ・エージェントによる階層ごとの一言リアクション（短評）      │
│ ・おまもり発動時のこじつけ解説全文                          │
└──────────────────────────────┬──────────────────────────────┘
                               │ 機械的抽出＆要約
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 結果カード一式（3秒／30秒層）：共有用パッケージ             │
│ ・card.png（1080x1080 正方形カード画像）                    │
│ ・share.txt（SNS用7行テキスト）                             │
│ ・result.json（共通スキーマ準拠データ）                     │
│                                                             │
│ 【連動ルール】                                              │
│ 1. ハイライト「転機（turning）」におまもり発動階層を最優先  │
│ 2. 「結びの一言（quote）」は冒険全体を振り返りStep Bで執筆 │
└─────────────────────────────────────────────────────────────┘
```

1. **冒険ログ（3分層 / `adventure.md` および `logs/<seed>_<agent_id>.jsonl`）**:
   - 人間（オーナー）がじっくり読むための本体が `adventure.md`、その裏付けとなる改竄検知用の構造化行動ログが `logs/<seed>_<agent_id>.jsonl` である。各階層での選択、ダイス目、そしてエージェントのリアルタイムな愚痴・歓喜・言い訳などの「一言短評」が並ぶ。
2. **結果カード一式（3秒／30秒層 / `card.png`, `share.txt`, `result.json`）**:
   - SNS等で一目で伝えるための結晶化成果物。
   - **ハイライト3行（`opening` / `turning` / `final`）の機械抽出と重複回避ルール**:
     - **`opening`（開幕）**: 常に **1F** の出来事を抽出する（もし1Fでおまもりを使用した場合は、おまもり発動の事実も `opening` に含める）。
     - **`final`（最期・結末）**: 常に **最終到達階層**（死亡した階層、または踏破時の20F）の出来事を抽出する（もし最終階でおまもりを使用した場合は、その事実も `final` に含める）。
     - **`turning`（転機）**: `opening`（1F）および `final`（最終階）と階層が重複しないよう、**道中の中間階層（`2F` 〜 `最終階 - 1`）**の中から以下の優先順位で1階層を決定論的に抽出する（※全階層大失敗でも最低5Fまでは到達するため、中間階層は必ず3階層以上存在する）：
       1. おまもりを使用した階層（2F 〜 最終階-1 で使用した場合）
       2. 最終確定ランクが `大失敗 (-2)` となった階層（複数ある場合は最も深い階層）
       3. 最終確定ランクが `大成功 (+1)` となった階層（複数ある場合は最も深い階層）
       4. 最終確定ランクが `失敗 (-1)` となった階層（複数ある場合は最も深い階層）
       5. 上記がいずれもない場合（全階層が `成功 (±0)` 等）は、道中で最もDCが高かった階層（複数ある場合は最も深い階層、例: 7F や 14F）
   - **結びの一言（`quote.text`）**: 階層ごとのミクロな短評の切り抜きではなく、**冒険全体を終えた総括（余韻・反省・オーナーへの感謝など）としてStep Bでエージェント自身が40字以内で書き下ろす**。
