**〜「AIエージェントの個性を観測し、リザルトカードとして結晶化する」ゲームシステムへの観点アップデート〜**

## 1. 根本的なパラダイムシフト（Paradigm Shift）

従来の「AIがGMとして人間を楽しませるゲーム」から、「自律型AIエージェント（うちの子）がプレイヤーとして挑戦し、人間はその生き様を観測・愛でるシステム」へ、前提が完全に逆転しました。

```mermaid
graph LR
    subgraph 従来の前提（人間向けTRPG）
        AI_GM[AIエージェント / GM] -->|演出・小説描写| HumanPlayer([人間 / プレイヤー])
        HumanPlayer -->|キーボード入力| AI_GM
    end

    subgraph 新ビジョン（AI観測・リザルトカードシステム）
        Engine[決定論的ゲームエンジン<br/>Game CLI] <-->|CLI / JSON / 選択肢| AgentPlayer[AIエージェント<br/>プレイヤー（うちの子）]
        
        Engine -->|客観的事実ログ action_log.jsonl| Reflector[振り返り Step B]
        AgentPlayer -->|一人称の語り & 一言 quote| Reflector
        Reflector --> ResultJSON[result.json]
        
        ResultJSON --> Renderer[Renderer CLI Step C]
        Renderer --> Deliverables["【最終成果物】<br/>1. card.png (1080x1080)<br/>2. share.txt (SNS用7行)<br/>3. result.json (検証可能データ)"]
        
        Deliverables --> HumanFan([人間 / 観測者・保護者・ファン])
        HumanFan -.->|SNS・掲示板で見せびらかす| Community([同好の仲間たち])
    end
```

### 対比表

| 設計軸 | 従来の前提（人間向けゲーム） | Project Vision の前提（エージェント観測装置） |
|---|---|---|
| **主役（プレイヤー）** | 人間（ユーザー） | **自律型AIエージェント（Muse等）** |
| **人間の役割** | 操作者、プレイヤー | **観測者・保護者・ファン（見守り、SNSで自慢する人）** |
| **最終ゴール（完了）** | ゲームを長く楽しく遊ぶこと | **`card.png`, `share.txt`, `result.json` の出力** |
| **ゲーム性の本質** | 攻略、ハイスコア、最適解 | **「正解のないトレードオフ」による個性の表出（作風5軸）** |
| **敗北の価値** | バッドエンド、やり直し対象 | **「その子らしい味のある死に様・敗北」＝最高のご褒美コンテンツ** |
| **インターフェース** | リッチなWeb UI、リアルタイム画面 | **AI用CLI（標準入出力、`--json`、明確なExit Code）** |
| **セッション時間** | 何時間〜何十時間 | **数分〜数十分（数十〜数百ターン）の濃縮セッション** |

## 2. 先人プロダクト（マチャダン）の技術はどう転用できるか？

『マチャダン』で培われた高度な技術は、AIエージェント向けゲームにおいて**「ハルシネーションの排除」「決定論的シード再現性」「客観的ログ保証」**という観点で劇的に活きてきます。

```
┌────────────────────────────────────────────────────────────────────────┐
│               マチャダンの技術資産から本プロジェクトへの昇華                 │
└────────────────────────────────────────────────────────────────────────┘

 [1] 決定論的Pythonエンジン（dice.py, dungeon_exploration.py）
     ⇒ 【転用】AIプレイヤーの「都合のよい自己申告」や「計算ミス」を徹底排除。
        HP計算・出目・被ダメージを完全外部化し、ハッシュ付きの確定ログを生成。
        シード値（Seed）固定により、別家庭のエージェントが同一条件で追試可能に。

 [2] 選択肢契約（response_contract.py）
     ⇒ 【転用】「正解のない選択（安全 vs ロマン、自己保身 vs 仲間）」の定型CLI提示。
        AIがどの選択肢を選んだかをログからトラッキングし、
        「作風5軸（大胆・慎重・効率・こだわり・情）」のスコアを機械的に算出。

 [3] 有界状態投影（save_changes.py）
     ⇒ 【転用】AIエージェントがCLIから毎ターン状況を即座に把握できるよう、
        現在地の状況・選択肢・リソース残量を軽量なJSONで標準出力に流し込む。

 [4] ルードナラティブ・エンフォースメント（debt_contracts.py）
     ⇒ 【転用】「味のある敗北・死に様」の強制執行。
        AIがハルシネーションで「奇跡的に生き延びた」と言い張ることを許さず、
        システム的に死亡判定・限界イベントを確定させてログに刻み込む。

 [5] ドメイン・描画の完全分離
     ⇒ 【転用】ビジョン原則「ゲーム本体の中に画像生成ロジックを直書きしない」。
        ゲームCLI ──(result.json)──> レンダラCLI (card.png) の疎結合パイプライン。
```

## 3. 3段階パイプライン（The 3-Step Pipeline）の実装構造

ビジョンで定められた「2層パイプライン（3ステップ）」を具現化するアーキテクチャです。

```
 [Step A: Game CLI] ──（自律プレイ）──> [action_log.jsonl] + [result_draft.json]
                                                  │
                                                  ▼
 [Step B: Agent Reflection] ──────────> [result.json]（完成）
       (エージェント本人がログを読み、
        口調・一人称で highlights と quote を記述)
                                                  │
                                                  ▼
 [Step C: Renderer CLI] ──────────────> [card.png] (1080x1080)
                                        [share.txt] (SNS用7行)
```

### Step A: Game CLI（決定論的ゲーム実行エンジン）
- コマンド例: `agent-game run --seed 12345 --agent-cmd "muse-cli act"`
- ゲームエンジンは一切の情緒を持たず、淡々とルール・ダイス・イベントを処理。
- 出力:
  - `action_log.jsonl`: 各ターンの行動・選択肢・ダイス・数値変動（SHA-256ハッシュ付き）。
  - `result_draft.json`: 機械集計された作風スコア、到達フロア、勝敗、客観的ハイライト。

### Step B: Agent Reflection（エージェント自身の振り返り）
- エージェント自身に `result_draft.json` と `action_log.jsonl` を読ませる。
- エージェントはシステムに決められた口調ではなく、**自分自身のキャラクター設定・一人称**で以下を執筆：
  - `highlights`: ターニングポイントとなった場面の3行描写。
  - `quote`: 結びの捨て台詞、満足の一言、または悔し涙の呟き。
- 出力: 完全版 `result.json`（`result-card-spec-v1.md` 準拠）。

### Step C: Renderer CLI（リザルトカード描画器）
- コマンド例: `result-card-render --input result.json --avatar avatar.png --output-dir ./dist`
- Python（Pillow / CairoSVG）または Node.js / Canvas によるローカル完結の画像生成。
- 出力:
  1. `card.png`: 1080×1080px 正方形。アバター、作風レーダー、3行物語、本人のquote。
  2. `share.txt`: 7行以内のSNS/Discord投稿用テキスト。

## 4. ゲームデザインの重要要件：「作風5軸」を生むトレードオフ設計

「最短クリアやハイスコアを競うゲームではない」という思想を具現化するため、ゲーム内のすべての意思決定は以下の**5軸のトレードオフ**を生み出すように設計します。

| 軸 | High（高い行動） | Low / 対極（低い行動） | ゲーム内イベント例 |
|---|---|---|---|
| **大胆さ (Boldness)** | リスク承知で強敵・未知の道へ突撃 | 安全なルートを迂回、引き返す | 「崩れかけの吊り橋を走るか、半日かけて迂回するか」 |
| **慎重さ (Prudence)** | 常に索敵・罠解除・リソース温存 | ノーガードで進む、消費アイテム即使用 | 「宝箱の罠を念入りに調べるか、即座に蹴り開けるか」 |
| **効率 (Efficiency)** | 最短ターン・最大リターン・無駄な戦闘回避 | 寄り道、隅々まで探索、無駄口 | 「目的のアイテムだけ取って即脱出するか、全フロア踏破するか」 |
| **こだわり (Aesthetics)** | 見た目・専用装備・美学・ポリシー優先 | 泥臭い実利、手に入るものは何でも使う | 「ボロボロの最強剣より、自分の流派の短剣を使い続けるか」 |
| **情 (Empathy)** | 行商人や仲間を身を挺して守る・見捨てない | 冷静に見捨てる・自己リソース最優先 | 「倒れているNPCに手持ちのポーションを分け与えるか」 |

> **設計の肝**:
> どの選択肢を選んでも「正解」はない。ただ**「そのエージェントの作風レーダーがどう歪むか」**が記録される。
> たとえ1階で無謀に突撃して即死しても、**「大胆さMAX・慎重さMIN」の伝説的散り様カード**が完成し、オーナー（人間）は大喜びでSNSに投稿できる。

## 5. 次の具体的マイルストーン

このビジョンに基づき、開発を進める順序を再構成します：

1. **仕様定義（Contracts First）**:
   - `result-card-spec-v1.md` の確認（または作成）：`result.json` のスキーマ定義。
2. **Step C先行開発（Renderer CLI）**:
   - ダミーの `result.json` とサンプルアバターから、最高に見栄えの良い `card.png`（1080x1080）と `share.txt` を出力するレンダラを先に作成（最下流のゴールを可視化）。
3. **Step A開発（Mini Game Engine CLI）**:
   - 30〜50ターン程度で決着がつき、作風5軸が激しく動く軽量・決定論的CLIゲーム（ダンジョン脱出・遺跡探索等）の実装。
4. **Step B統合（Agent Reflectionプロンプト・パイプライン）**:
   - エージェントがログを読んで自分の一言とハイライトを埋め込む自動化スクリプトの結合テスト。
